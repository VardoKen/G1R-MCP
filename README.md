# G1R MCP

Инструмент разработки официальных модов Gothic 1 Remake через MCP: пакеты `GothicMod.json`, AngelScript и подтверждённые игровые вызовы. Рабочая версия **1.0.0-dev.99**, целевая публичная версия **1.0.0**.

## Текущее состояние на 04.11.2026

Согласованный функциональный объём [PLAN-001](docs/mods/G1R_MCP/plans/PLAN-001-active-implementation.md) реализован: 51 MCP-инструмент для справочника API и исходников, работы с пакетами, диагностики и development-сеанса, объектов и состояния, снимков и сравнения, наблюдений и типизированных действий. Чтение поддерживает вложенные отражённые структуры и массивы; набор типов аргументов и результатов определяется проверенной сигнатурой конкретной функции.

Игровой маршрут — общий MCP-сервер → локальный TCP → собственная `G1R_MCP.dll` → очередь игрового Tick → отражённый вызов. UE4SS для этого не используется. Все чаты подключаются к одному HTTP-серверу; создание чата не запускает новый сервер.

Перенос модов уже можно вести этим инструментом. Наличие инструмента не доказывает доступность любого API: типы, сигнатуры и результат выбранного вызова подтверждаются отдельно. Перезагрузка тел AngelScript-функций проверена; изменения классов, свойств и defaults требуют перезапуска. Создание и cooking ресурсов относятся к отдельному Modkit/редактору. Чтение native compiler reports реализовано; пустой отчёт сам по себе не доказывает успешную компиляцию, произвольное исполнение AngelScript и универсальный debugger не заявлены.

Runtime-комплект и Python wheel dev.99 подготовлены. Wheel содержит сервер; DLL, загрузчик, PowerShell-инструменты и development-helper поставляются отдельным runtime-комплектом, задаваемым через `--runtime-root`. Это внутренняя поставка: публичный релиз `1.0.0`, загрузка в PyPI и установка runtime через Steam не подтверждены.

[Итоги проверок и точные границы подтверждения](docs/tests/G1R_MCP/README.md), [состояние этапов плана](docs/mods/G1R_MCP/plans/PLAN-001-active-implementation.md) и [история завершённых задач](docs/mods/G1R_MCP/task-history/README.md) ведутся у соответствующих владельцев. Старые результаты dev.1–dev.14 относятся к прежним версиям, а не к текущему состоянию.

## Подключение MCP

В текущей установке Codex используется общий адрес `http://127.0.0.1:27124/mcp`.

Из корня подпроекта:

```powershell
uv sync --locked
.\tools\start_shared_mcp.ps1 -Json
```

Повторный запуск использует уже работающий сервер. У текущего Windows-окружения могут быть два связанных процесса Python: загрузчик виртуального окружения и сервер. Эта пара общая для всех чатов. После перезагрузки Windows сервер запускается указанной командой; автозапуск этим скриптом не устанавливается.

Начало работы через MCP: `g1r_status` → `g1r_capabilities`. Они проверяют сервер и каталог, но не живую игру. Для игрового состояния используется `g1r_native_status`; для нового development-сеанса — `g1r_development_recipe` и `g1r_development_processes`, затем необходимые операции запуска, загрузки DLL и проверки готовности. [Подробный маршрут и совместная работа](docs/mods/G1R_MCP/native-route.md).

Отдельный stdio-клиент также поддерживается:

```powershell
.venv\Scripts\python.exe -B -m g1r_mcp.server `
  --modkit-root '..\G1R-Modkit' `
  --workspace-root '.' `
  --runtime-root '.'
```

Этот режим запускает отдельный дочерний сервер и не является конфигурацией общего HTTP-подключения Codex. MCP-сервер сам по себе игру не запускает.

## Сборка и внутренняя поставка

Python **3.11+**, SDK **mcp 2.3.0**; зависимости фиксируются `uv.lock`. Python packaging нормализует `1.0.0-dev.99` до `1.0.0.dev99`.

В текущей рабочей базе для нативной разработки используется существующий incremental-каталог `artifacts/build-dev64`. Сборку DLL проводят одной группой после изменений, без повторного configure для каждого исправления. Сборка удерживаемой игрой DLL требует завершения соответствующей игровой сессии. Команды первоначальной сборки, загрузки и runtime-зависимости описаны в [нативном маршруте](docs/mods/G1R_MCP/native-route.md).

`tools/prepare_bridge_bundle.py` подготавливает внутренний runtime-комплект с проверяемым manifest; `--verify-root` сверяет его содержимое без запуска игры. `tools/export_script_package.py` упаковывает официальный скриптовый пакет. Упаковка и структурная проверка не заменяют компиляцию и загрузку выбранного пакета игрой.
