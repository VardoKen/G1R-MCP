# Локальные MCP-инструменты — 1.0.0-dev.9

Дата: **31.10.2026**. Э4 PLAN-001: поиск официальных источников, рабочие пакеты и управление development-сеансом. Код серверной части: `src/g1r_mcp/`, официальный Python SDK `mcp==2.3.0`, stdio. Игровой доступ описан отдельно в [нативном маршруте](native-route.md); операции запуска, остановки и загрузки DLL имеют явно обозначенный эффект.

`g1r_create_package` и `g1r_write_package_file` изменяют выбранную рабочую базу; development-start/stop и native-load изменяют внешнюю среду. Остальные перечисленные операции читают данные. Корень Modkit, рабочая база и корень игры задаются при запуске сервера. Источники ограничены `Script/` и `Examples/<пример>/Script/` официального Modkit; остальные файлы не читаются через инструмент исходников. Каталог Modkit защищён от записи даже при вложенности внутри рабочей базы. Валидатор читает дескриптор и считает скрипты внутри выбранного пакета.

Development-рецепт связывает проверенный дескриптор с полным SHA-256 manifest: максимум 10 000 файлов/каталогов, 16 МиБ на файл, 64 МиБ суммарно и 768 КиБ сериализованного manifest; частичный рецепт не возвращается. Start проверяет ожидаемый manifest, stop/load — PID, точное время создания и полный EXE, load дополнительно закрепляет SHA-256 и открытый файл DLL. Фиксированные инструменты вызываются без shell с пределом 30 секунд и ограниченным выводом; при неопределённом исходе операция автоматически не повторяется. `launch_requested` подтверждает только запрос Steam, `loaded` — загрузку DLL; компиляция, Tick и активация пакета проверяются отдельно. Development file watcher подтверждён для изменения тела функции, но запись файла не выдаётся за завершённый hot reload.

Initialize-инструкция и `g1r_capabilities.bootstrap` дают реальные имена и порядок запуска/загрузки/Tick/сигнатуры/вызова/остановки, примеры форм аргументов и правила владения. `g1r_status` сообщает настроенные корни, но сохраняет `connection_checked: false` и `ready_known: false`: живую готовность проверяет `g1r_native_status`. Полный каталог содержит все 32 инструмента, включая локальное сравнение снимков.

В dev.9 `enable_ingame_tools` принимает только JSON bool и по умолчанию равен `false`. Значение хранится в `launch_options.enable_ingame_tools` и входит в manifest SHA-256: для смены флага после рецепта требуется новый рецепт/хеш. Игровая MCP-проба 31.10.2026 с `true` подтвердила автоматический `Initialize` собственного `UIngameTool` в главном меню; CDO остался неинициализированным, callback вручную не вызывался. World lifecycle этим не подтверждён: runtime-компилятор отклонил override отдельной world-fixture.

Дескриптор объекта dev.9 проверяет строгое равенство наблюдаемых serial объекта и класса вместе с identity класса, включая zero. `serial_guard.policy = strict_observed_equality_including_zero`, `coverage = conditional_on_observed_nonzero_object_and_class_serial`, `zero_aba_protection = false`, `allocates_serial = false`. Переход zero к ненулевому serial отзывает старый handle; смена мира ещё не имеет отдельного подтверждённого поколения.

## Создание и редактирование пакета

Новый пакет создаётся только в отсутствующем каталоге с существующим родителем. Инструмент записывает `GothicMod.json` и создаёт пустой `Script/`; игровые классы и обязательная точка входа не генерируются. Для файла разрешены `GothicMod.json`, `Script/**/*.as` и `ScriptPatches/*.patch`. При первой записи `.patch` создаётся только документированный каталог `ScriptPatches/`; другие родительские каталоги должны существовать. Вложенные патчи и иные расширения отвергаются.

`g1r_create_package_directory` явно создаёт недостающие каталоги `Script/` с подкаталогами либо корневой `ScriptPatches/`, максимум 32 компонента пути. Существующий корректный каталог возвращается без повторного создания. Перед первым mkdir проверяются дескриптор, все назначения и защищённые корни; ссылки, конфликт с файлом и недопустимые компоненты отвергаются. При отказе удаляются только пустые каталоги, созданные этой операцией; постороннее содержимое сохраняется.

Пакет только с `ScriptPatches/` допускается структурной проверкой. Патчи считаются отдельно от `.as`; локальная валидация не применяет diff к игровым исходникам и возвращает `patch_validation: "not_performed"`. Подготовленная [проба патча](../../../tools/prepare_patch_probe.py) проверена автономно через `git apply --check` и применение к изолированному исходнику; это не доказательство применения игровым загрузчиком.

`g1r_build_script_patch` принимает только `Script/**/*.as` официального Modkit и ожидаемый SHA-256 его полных байтов. Исходник/замена ограничены 1 МиБ, diff — 2 МиБ, контекст — 0–20 строк. CRLF, UTF-8 BOM и отсутствие завершающего LF сохраняются; одиночный CR отвергается. Изменившийся исходник вызывает `conflict`, одинаковые байты дают пустой diff. Результат можно записать в рабочий `ScriptPatches/*.patch` обычным инструментом записи; `engine_apply: "not_performed"` и `compiled: false` сохраняются. Полный SHA-256 возвращается и при чтении только части строк, поэтому фрагмент текста не следует использовать как полную замену без самостоятельной сборки всего содержимого.

Для редактирования целого файла используются `g1r_read_source_exact` и `g1r_read_package_file_exact`: `text.encode("utf-8")` воспроизводит исходные байты, включая BOM, CRLF и отсутствие завершающего LF. Ответ содержит полный SHA-256 и `text_mode: "exact"`; превышение предела вызывает `file_too_large` без усечённого текста. Предел полного чтения — 1 МиБ для исходника/рабочего `.as`/`.patch`, 256 КиБ для дескриптора. Построчные инструменты сохраняют назначение просмотра и возвращают нормализованный фрагмент; его нельзя принимать за точную полную замену.

Без `expected_sha256` допускается только создание отсутствующего файла. Для замены нужен SHA-256 полных байтов, полученный при чтении; изменённый или исчезнувший файл вызывает `conflict`. Кандидат дескриптора проходит структурную проверку до замены. Записи одного назначения сериализованы между MCP-процессами; каталоги защищены от замены на Windows. Хеш проверяется непосредственно перед заменой, но это не блокирует произвольный внешний редактор от записи после проверки. Отказы удаляют промежуточные файлы.

Пути с `..`, абсолютными компонентами, Windows device names, alternate streams, ссылками, junction и reparse points отвергаются. Содержимое должно быть UTF-8 без NUL; предел `.as` и `.patch` — 2 МиБ, дескриптора — 256 КиБ. Список ограничен 200 результатами и 10 000 файлами исходников/патчей, чтение — 400 строками и 64 КиБ текста. Ответы сохраняют `compiled: false` и `runtime_validation: "not_performed"`.

Для полного обхода списка используется `offset` в диапазоне `0..10000`, следующий запрос получает возвращённый `next_offset`, пока `has_more` не станет `false`. Страницы сортируются по относительному пути; `snapshot_atomic: false` сохраняет границу последовательного чтения файлов. Изменение каталога между страницами не выдаётся за единый атомарный снимок.

## Сравнение копий снимков

`g1r_compare_snapshots` не обращается к DLL. Входные копии ограничены 1 МиБ каждая, 16 объектами и 32 свойствами на объект; результат — 200 записями и 1 МиБ. При смене процесса или сессии результат `comparable: false`. Различаются изменение значения/типа, изменение охвата и недоступное свойство/объект. Неполный охват не выдаётся за доказанное равенство; отсутствие цели не означает уничтожение объекта.

`ObjectProperty` содержит `null` либо точный дескриптор `{handle,index,name,path,class,session_id}` без адресов памяти. Сессия значения должна совпасть с сессией снимка; имя/класс ограничены 4096 байтами UTF-8, путь — 8192, handle — 80. Переход `null ↔ ссылка` считается изменением значения, без изменения объявленного типа. Противоречащая metadata прежнего handle даёт неизвестный результат; стабильные ссылки допускают сравнение копий и наблюдение за объектными полями.

`ClassProperty` использует тот же непрозрачный дескриптор либо `null`; в вызове принимается `null` или `{handle}`. Нативный слой проверяет, что значение является UClass и соответствует отдельно отражённым PropertyClass/MetaClass, включая производные классы. Это отличается от передачи обычного CDO. Копия снимка не доказывает такую runtime-проверку: произвольное имя метакласса сохраняет `provenance: "unverified"`; переход `null ↔ класс` меняет значение, а изменение `ObjectProperty ↔ ClassProperty` — объявленный тип.

`NameProperty` читается как текст FName. `EnumProperty` и `ByteProperty` сохраняют числовое значение; enum-метаданные содержат путь, базовый тип, статус имени, имя значения, число совпадений, неоднозначность и причину недоступности. Отказ поиска имени не отменяет успешно прочитанное число. Сравнение чисел не зависит от label; метаданные выдаются отдельно как ограниченные before/after annotations. Plain `ByteProperty` проверяется как целое `0..255`, включая случай без enum-метаданных.

В dev.7 через MCP подтверждены нулевые входы с возвратом `NameProperty` (8 байт) и `StrProperty`/FString (16 байт): FName-entry/`None`, строка/пустая строка. Это контракт возврата, а не разрешение FName/FString-входов; out/ref остаются неподдержанными. Выделенный FString освобождается после копирования результата; ошибка копирования после вызова сохраняет выполненный эффект и запрет повтора.

В dev.8 `EnumProperty`/`ByteProperty` допускают целочисленный аргумент и возврат по отражённому underlying-типу/размеру. JSON bool, дробное число, строковое имя и значения вне диапазона отвергаются. Для объявленного UEnum вход должен совпасть с его значением; таблица и layout повторно проверяются перед `ProcessEvent`. Возвращается число, а имена/неоднозначность — отдельные `return_enum`-метаданные. В пробе прошли значения `0`, `1`, `7` с Byte underlying размером 1; девять неправильных входов не изменили счётчик вызовов. Строковые входы enum, структуры и контейнеры не добавлены.

Происхождение присланных клиентом копий не проверяется: `validation: "client_supplied_copies"`, `provenance: "unverified"`. Значения и вложенные ошибки ответа копируются; входные структуры не изменяются. Формы нативного снимка и наблюдений описаны в [нативном контракте](native-route.md).

## Полнота и происхождение

Поиск выдаёт источник `official_modkit_static`, подтверждение `source_only`, метку ревизии, число совпадений, предел и признаки неполноты. Метка `--source-revision` задана клиентом и не доказывает неизменность всей рабочей копии. Чтения последовательны и не являются атомарным снимком.

Лексический индекс не является AST компилятора, не включает все нативные bindings и не подтверждает существование объектов или безопасность вызовов в игре. Пропущенные слишком большие/нечитаемые исходники и усечение выдаются явно; при неполном охвате число совпадений является нижней границей. Прямое чтение неподходящего файла выдаёт ошибку.

Результаты ограничены: предел списка 1–200, чтение 1–400 строк и 64 КиБ UTF-8 текста, запрос до 512 символов, исходник до 2 МиБ. Эти ограничения — контракт локального инструмента, а не предел возможностей игры. Символические ссылки, junction и выход за разрешённые корни отвергаются. Изменение файла во время чтения не выдаётся за стабильный результат.

Для runtime-сигнатуры `g1r_object_functions` принимает необязательный `function_query`: фильтр применяется до ограничения результата, поэтому нужная функция не теряется среди первых 200 нерелевантных записей. Параметры читаются из отражённой цепочки параметров; пределы/ошибки сканирования и усечение выдаются явно. Это игровой read-only инструмент, не часть лексического индекса.

## Проверка пакета

`valid_structure` означает только корректность локально проверенных полей/компонентов. Ответ всегда содержит `runtime_validation: "not_performed"` и `compiled: false`. `Script/` может отсутствовать у пакета контента; `main.lua` или выдуманный `main.as` не требуются.

`modVersion` проверяется как непустая строка, а не как доказанная версия загрузчика. Техническая строка `1.0.0-dev.1` может пройти структурную проверку, но её принятие игрой не проверено. Неизвестные поля дают предупреждение, некорректный JSON/дубли/типы — ошибки. Сохранения, cache, установки модов и постоянные настройки не затрагиваются.

[export_script_package.py](../../../tools/export_script_package.py) экспортирует проверенный скриптовый пакет в детерминированный ZIP и manifest: только `GothicMod.json`, `Script/**/*.as`, `ScriptPatches/*.patch`. Постороннее содержимое отвергается, источники сохраняются; хеши проверяют исходные байты и архив. Экспорт не компилирует, не устанавливает и не применяет патч; это CLI-инструмент, количество MCP-операций остаётся 32.

## MCP и ошибки

Локальные функции имеют input schemas и структурированные object-ответы официального SDK. `catalog_revision` — версия контракта инструментов сервера, не ревизия содержимого Modkit. Предсказуемые ошибки исходников/пути возвращаются как `is_error` с JSON-кодом и русским сообщением. Создание и запись помечены как операции с эффектом; конфликт не разрешается скрытой перезаписью. Нативные операции имеют отдельные признаки эффектов и доступности; неподдержанные группы не выдаются за реализованные.

Пройдены реальные MCP stdio-сессии на изолированных данных: источники и валидация, создание/чтение/замена пакета, конфликт хеша, запрет записи в Modkit, сравнение фактических форм снимков и сохранение файлов при отказах. [Команды и проверенный набор](../../tests/G1R_MCP/README.md).

Проверка на текущем Modkit охватила **7 292** файла: 7 280 игровых и 12 скриптов примеров. Найден `UGameTimeConfigG1R`, подтверждено ограниченное чтение его исходника. Полный лексический проход занял около **32 секунд** и явно пропустил два файла больше 2 МиБ (`WorldPointManagerConfig_MainMap.as`, `VoiceTypes.as`). Это ограничение dev.1: индекс строится последовательным чтением без кеша, высокая задержка полного поиска типов ещё не устранена. Статус и другие MCP-запросы обслуживаются независимо от длительного sync-обработчика через официальный SDK.
