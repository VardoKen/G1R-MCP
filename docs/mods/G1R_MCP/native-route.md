# Нативный маршрут — 1.0.0-dev.5

Дата: **30.10.2026**. Назначение: внутренний рабочий мост для разработки модов, без подготовки публичного выпуска. Пользователь прямо поручил собрать собственный нативный маршрут и допускает экспериментальную стабильность. Приоритет — доступ к текущей игре сейчас.

## Реализованная цепочка

```text
ИИ / MCP-клиент
  ↕ stdio, официальный Python MCP SDK
G1R MCP Server
  ↕ TCP 127.0.0.1:27123, uint32BE + UTF-8 JSON
G1R_MCP.dll в процессе игры
  ↕ ограниченная очередь из FEngineLoop::Tick
UObject / UFunction / ProcessEvent
  ↕
Нативные и отражённые AngelScript-функции игры
```

DLL не зависит от UE4SS и не копируется в игру. `g1r_mcp_loader.exe` загружает её из `build/native/Release/` в проверенный игровой PID. Загрузчик проверяет путь/архитектуру процесса, собственный путь DLL и фактический системный модуль `LoadLibraryW`; повторная загрузка того же файла не увеличивает число подключений.

DLL живёт до завершения процесса. `FreeLibrary` и остановка/удаление перехвата в работающей игре не поддерживаются. Чтобы отключить мост, закрыть игру и запустить её без загрузчика. Для пересборки DLL закрыть игру: Windows удерживает загруженный файл.

## Подключение

Из корня подпроекта:

```powershell
uv sync --locked
.\tools\build_native.ps1
.\tools\start_g1r_development.ps1
```

После открытия главного меню:

```powershell
.\tools\load_native.ps1
.venv\Scripts\python.exe -B tools\probe_native_route.py --enable --call-verified-as
```

`start_g1r_development.ps1` использует Steam AppID `1297900`, сохраняет `-FromModManagementUI` и разовые параметры разработки. Существующий выбор модов, Steam LaunchOptions и cache не изменяются. `load_native.ps1` только подключает DLL к уже запущенной игре. Выполнение `--enable` до готовности игры может не сразу дать `ready`; probe ограниченно ждёт подтверждённый Tick, не повторяя игровые действия.

Для MCP-клиента сервер запускается через stdio. Пример параметров клиента, не установленный автоматически в конфигурацию приложения:

```json
{
  "command": "C:/Users/Vardo/Documents/G1R Mods/G1R MCP/.venv/Scripts/python.exe",
  "args": [
    "-B", "-m", "g1r_mcp.server",
    "--modkit-root", "C:/Users/Vardo/Documents/G1R Mods/G1R-Modkit",
    "--workspace-root", "C:/Users/Vardo/Documents/G1R Mods/G1R MCP",
    "--native-port", "27123"
  ],
  "cwd": "C:/Users/Vardo/Documents/G1R Mods/G1R MCP"
}
```

В сессии сначала `g1r_native_status`; если DLL загружена, но hook ещё не установлен — один `g1r_native_enable`, затем проверка `ready`. Эти инструменты не запускают игру и не выполняют загрузчик.

## Нативные инструменты

| Инструмент | Назначение |
| --- | --- |
| `g1r_native_status` | Живая версия, проверенный EXE, состояние hook, Tick и игрового потока |
| `g1r_native_enable` | Установить перехват и очередь Tick в уже загруженной DLL; повтор при включённом hook не устанавливает второй |
| `g1r_find_objects` | Поиск по части имени/класса, ограниченный список и непрозрачные ссылки |
| `g1r_object_properties` | Отражённые свойства, значения поддержанных скалярных типов и признаки неподдержанных |
| `g1r_object_functions` | Функции объекта, владелец, параметры, размер буфера, типы и return/out/ref признаки |
| `g1r_invoke` | Один явный `ProcessEvent` на проверенном объекте с поддержанной сигнатурой |
| `g1r_snapshot` | Выбранные свойства до 16 объектов, скопированные последовательными чтениями на одном Tick |
| `g1r_compare_snapshots` | Локальное сравнение копий: изменения значений, типов, охвата и неизвестные результаты |
| `g1r_watch_start/read/stop/forget` | Наблюдение свойств на Tick с явным сроком, интервалом, буфером и подтверждённой остановкой |

Поддержаны входные `bool`, `int32`, `float`, `double`. Возврат: скалярные целые/вещественные, `bool`, `FString`; строковый результат копируется и освобождается игровым allocator. Входные строки, структуры, массивы, object-аргументы, out/ref пока отвергаются. Произвольная компиляция или выполнение глобальных AngelScript-функций не реализованы: доступ осуществляется через отражённые UFUNCTION.

Имя аргумента берётся из `g1r_object_functions`, а не угадывается по исходникам. `g1r_invoke` отмечен как потенциально изменяющий и неидемпотентный. Фактические эффекты определяются конкретной функцией; присутствие функции не доказывает безопасный вызов.

## Снимки, наблюдения и собственный AngelScript-пакет

Проверено 30.10.2026: реальный MCP stdio-клиент получил 23 инструмента, скопировал выбранные bool-свойства CDO `CM_Attack`, сравнил снимки и прошёл `start → read → stop → read → forget`. Финальное событие имеет `state=stopped`, `cleanup_complete=true`. На автономных моделях проверены изменения, переполнение, потери, срок, инвалидирование и disconnect; фактическая смена мира остаётся открытой.

Снимок ограничен 16 объектами, 32 полями на объект и 256 КиБ. `consistency=single_tick_sequential` означает последовательные чтения на одном Tick. Наблюдение: до 8 записей владельца, 128 событий и 256 КиБ в буфере; срок до 10 минут, интервал от 10 мс. Исполняется максимум одна готовая выборка за Tick без догоняющих чтений. `seq`, `gap`, `dropped_events`, `truncated` показывают потери и границы чтения. Неподдержанный начальный снимок не запускает наблюдение.

Официальный проверочный пакет из `tests/fixtures/angelscript_probe` подготовлен в `artifacts/compile-probe-dev3` и включён только через разовые `-ModsDirectory`/`-Mods`. Реально найдены `/Script/Angelscript.Default__G1RMCPCompileProbe`, класс `G1RMCPCompileProbe`, метод `ReadProbeValue()` с `IntProperty` возвратом 4 байта. Вызов вернул `1`; после изменения только тела — `2` без перезапуска. Это подтверждает компиляцию, загрузку и hot reload этого пакета, а не универсальный compiler API. Сохранения не загружались.

Воспроизводимые инструменты: `tools/prepare_compile_probe.py` готовит fixture и хеши; `tools/probe_live_mcp.py --expected-value 2 --observations --observe-query Default__CM_Attack --observe-class CM_Attack --property bRequiresNonDefeatedTarget` проверяет реальные MCP-вызовы без автоматического запуска игры. Для исходного baseline использовать новый каталог и `--expected-value 1`.

## Объектные ссылки и развитие рабочего цикла — dev.4

Проверено 31.10.2026 через реальный MCP: три CDO собственного пакета, сигнатуры и маркеры `41`/`99`; `ReadSelf`, `EchoObject` и `EchoTypedObject`, `null` и наследник, отказ постороннему классу до выполнения, bool-возврат за отражённым `ParmsSize`. ObjectProperty копируется как `null` или `{handle,index,name,path,class,session_id}`. Повторная копия актуального объекта переиспользует handle, поэтому наблюдение не создаёт ложные события. Проверены изменение поля, один changed event, восстановление null, stop/forget и отказ старой ссылки после новой сессии.

Разрешён точный ObjectProperty размером 8 байт. Объявленный класс проверяется по подтверждённому PropertyClass+0x70 из официального MemberVariableLayout; метакласс `/Script/CoreUObject.Class` подтверждён текущей игрой. ClassProperty, weak/soft/lazy и массивы остаются неподдержанными. Возвращаемые объекты повторно проверяются после копирования. Риск serial/ABA не устранён.

`g1r_find_objects` принимает `exact_path`; запросы с `/` или `.` также ищут по пути. Ошибка после успешного ProcessEvent сохраняет `effect.executed=true` и `do_not_retry=true`; ошибка проверки аргумента — `may_have_executed=false`. Это исключает подмену выполненного действия простым отказом получения результата.

Полный development-контур доступен через `g1r_development_recipe`, `g1r_development_processes`, `g1r_development_start`, `g1r_native_load`, `g1r_development_stop`: манифест пакета, идентичность процесса и хеш DLL проверяются перед действием. Рецепт и ответ Steam не подтверждают компиляцию. Загрузка DLL не включает Tick автоматически; затем требуются status/enable и runtime-проба. `tools/probe_development_mcp.py` воспроизводит этот цикл и закрывает созданную игру в finally.

31.10.2026 полный development-цикл через реальный MCP с 28 инструментами прошёл: recipe → start → точная идентичность процесса → load → status/enable → первый Tick → сигнатура → ReadProbeValue=2 → stop. Остановка подтверждена, процессов игры после пробы нет. Холодный старт потребовал больше 15 секунд до первого Tick; воспроизводимая проба ждёт до 45 секунд без повторной загрузки DLL.

Эксперимент ScriptPatches для нового исходника собственного пакета завершился значением `10`, хотя unified diff менял его на `11`. Класс и функция реально загружены, но изменение не применилось в этой конфигурации. Это не проверка патчей базового Script: официальная документация описывает именно их. Причина порядка/области применения не установлена. Синтаксическая ошибка fixture (пропущенный class) исправлена перед успешной пробой.

## Сессия и ограничения

- Один активный TCP-клиент, один запрос в полёте. MCP-сервер держит постоянное соединение; отдельная диагностическая утилита должна завершить соединение перед работой сервера.
- Ссылки и наблюдения принадлежат текущей сессии. После reconnect искать объекты заново. При лимите реестра сервер возвращает `handle_limit`, сохраняя существующие ссылки. Disconnect прекращает дальнейшие выборки и очищает владельца на игровом потоке.
- Проверяются слот, указатель, internal index, класс, имя и признаки начала/завершения уничтожения. Serial объекта не подтверждён; повторное использование памяти с совпадающими признаками остаётся ограничением экспериментальной версии.
- Кадр до 1 МиБ, глубина JSON ограничена; 1024 уникальных request ID на соединение. Повтор ID не вызывает обработчик второй раз, после предела соединение закрывается.
- Очередь ограничена восемью заданиями, один запрос на Tick. Ожидание — 2,5 секунды. Ещё не начатая работа отменяется; уже начатая после timeout может закончиться. Клиент не повторяет команду и сообщает `may_have_executed`.
- Действия исполняются только в первом подтверждённом потоке Tick. Нет маршрута исполнения игровых вызовов из сетевого потока.
- Частичный/неподдержанный результат отражён в ответе. Не все свойства и функции охвачены. Полный поиск объекта при отсутствии раннего совпадения может заметно занять кадр.
- Узкие не-ASCII FName и сложные свойства пока не имеют полного проверенного покрытия.
- Сбои игры возможны. В ходе разработки были ранние завершения процесса; после явного включения hook и готовности главного меню текущая вертикаль повторно прошла. Длительная работа, смена мира, загрузка сохранения и широкие игровые действия пока не проверены.

Диагностические `native-phase.log` и `native-tick.log` записываются рядом с DLL в игнорируемом `build/`. VEH только фиксирует адрес исключения и передаёт его дальше, не проглатывая сбой игры.

## FName, enum и точная редактура — dev.5

31.10.2026 через реальный MCP проверены `GA_Spell_Light.m_SocketName=spine_03`, `CM_Attack.AttackDirectionRequirement=0` с именем `EAttackDirectionRequirement::None` и `UsageType=1` с `EAttackUsageType::Regular`. Два полных снимка сравниваются без изменения значений и metadata. Числовое значение enum не зависит от доступности подписи; подписи и неоднозначность передаются отдельно. Новые типы добавлены для чтения свойств; аргументы и результаты invoke пока не расширены.

`g1r_read_source_exact` и `g1r_read_package_file_exact` сохраняют UTF-8 BOM, LF/CRLF и отсутствие финального newline. Для исходника и AS/patch предел 1 МиБ; для дескриптора 256 КиБ. Paged-чтение помечено `display_lines`. `g1r_build_script_patch` требует исходный SHA-256 и выдаёт детерминированный unified diff без записи Modkit. Содержимое и хеш реального CombatMoves.as через MCP побайтно совпали с источником.

Повторный полный MCP development-цикл с 31 инструментом прошёл: recipe/start/load/Tick/signature/маркер 2/stop. Остановка раннего bootstrap поддержана с привязкой ребёнка к исходному parent и времени его жизни. Игра после проверки закрыта. Автономная проверка: 252 Python-теста, CTest 5/5.

Внешняя Script-база требует `Binds.Cache` текущей игры. Первое отсутствие вызвало подтверждённый assert AngelscriptBindDatabase.cpp:104; после копирования только этого кеша в artifacts база скомпилировалась и загрузила контрольный класс. Установленные файлы не менялись. Патч к новой модовой функции оставил 10 вместо 11; патч к базовой ShouldInvalidateAttack оставил false вместо true, включая канонический git diff. Применение ScriptPatches в этих конфигурациях не подтверждено; активация пакета только с патчами отдельно не доказана. Дальнейших вариантов в этом блоке не добавляли.
