# Э0–Э1: среда, AngelScript и доступность канала

Дата: **30.10.2026**. Источники: установленная игра для чтения, Steam-манифест, официальный Modkit и справочник, открытый клиент Hazelight, разрешённые запуски игры и ограниченная статическая проверка EXE. Код игрового мода и MCP-сервера пока не создан.

## Решения пользователя

- Начать работу по PLAN-001; целевая публичная версия **1.0.0**.
- Полный инструмент разработки модов для ИИ-агентов: справочник, состояние игры, наблюдения, действия и разработка/проверка модов в подтверждённом контуре.
- Запускать игру **командами через Steam**, сохраняя маршрут с модами. Разрешены запуск development mode и штатное закрытие/перезапуск игры, запущенной агентом.
- Для исследования не загружать сохранения. Установка модов, изменение `Mods.ini`, cache и постоянных параметров запуска не поручались.

## Запуски и проверка debugger

Первые запуски были ошибочно сделаны напрямую из `G1R/Binaries/Win64`, затем через Steam без сохранения `-FromModManagementUI`. Пользователь указал, что эта среда не воспроизводит запуск с модами. Их отрицательные результаты **не используются как основание общей невозможности канала**.

Исправленный командный запуск:

```powershell
& 'E:\Steam\steam.exe' -applaunch 1297900 -FromModManagementUI -as-development-mode -as-ignore-precompiled-data -as-exit-on-error
```

Проверена цепочка **Steam → корневой штатный загрузчик → игровой EXE**. У игрового процесса присутствуют `G1R -FromModManagementUI -as-development-mode -as-ignore-precompiled-data -as-exit-on-error`. Это подтверждает маршрут и передачу аргументов; фактический список активных модов по нему не устанавливается. Существующий список модов и конфигурация не изменялись.

В текущем процессе после запуска и повторных проверок:

- `Get-NetTCPConnection` не обнаружил слушающих TCP-портов у игрового процесса;
- разовая проба `127.0.0.1:27099` вернула `WinError 10061`, соединение не установлено;
- не отправлены `StartDebugging`, `Evaluate` или другие запросы, поскольку соединение отсутствовало.

**Вывод:** debugger TCP-канал не предоставлен проверенным запуском. Нельзя считать этот результат доказательством невозможности любого официального IPC. Доставка в обработчик нашего мода, вызовы функций, поток исполнения и структурированный ответ пока не проверены.

Позднее найдено прямое подтверждение разработчика в [официальном обращении №1](https://github.com/AlkimiaInteractive/G1R-Modkit/issues/1) о том же отсутствии debug/language server. Сотрудник Alkimia `ataulien-alkimia` [ответил 30.10.2026 в 10:39 UTC](https://github.com/AlkimiaInteractive/G1R-Modkit/issues/1#issuecomment-6520702135): версия **1.1 не содержит LSP**, его включат в **следующем обновлении**. Это объясняет отсутствие обещанного language server в текущем выпуске; отдельные внутренние возможности debugger и пригодность будущего evaluator для MCP всё равно не считаются проверенными. Повторять одинаковые запуски до изменения сборки не требуется.

## Открытый протокол Hazelight

Источник: [vscode-unreal-angelscript](https://github.com/Hazelight/vscode-unreal-angelscript/tree/ffc7ab2948589abb04200b7dcedd326eaeaf7a4d), SHA `ffc7ab2948589abb04200b7dcedd326eaeaf7a4d`.

- Default endpoint клиента: `127.0.0.1:27099`; adapter version `2`.
- Исходящий кадр: LE `uint32`, длина включает однобайтовый тип. Входящий reader считает длину только payload после пяти байтов заголовка. Направления не симметричны.
- `RequestEvaluate=19`, `Evaluate=20`; запрос содержит строку и `frameId`, ответ — name/value/type/members. Корреляция клиента FIFO, идентификатора запроса в payload нет.
- Подтверждён исходящий ASCII; входящие строки поддерживают положительную UTF-8 длину и отрицательную UTF-16LE длину. Совместимость Unicode и протокола с G1R не проверена.
- Клиент подключается к существующему listener, а не включает сервер через специальный сетевой запрос.

Независимый ограниченный кодек и разовая проба реализованы в `tools/`. Это диагностический инструмент; он не даёт готового runtime backend и не выполняет произвольные выражения.

## API и ограничения текущей сборки

Официальный reference подтверждает описания:

- `FJsonObject::LoadFromString` / `SaveToString`, `FFileHelper::LoadFileToString` / `SaveStringToFile`;
- lifecycle `UScriptWorldSubsystem`: `Initialize`, `PostInitialize`, `OnWorldBeginPlay`, `Deinitialize`, `Tick`;
- события `UGothicModExt_WorldSubsystem`: готовность к игре, новая игра, загрузка сохранения, начало жизни игрока, создание/исчезновение NPC и другие документированные события;
- `System::ExecuteConsoleCommand` — исходящий вызов script → console, а не готовый внешний ingress;
- игровые примеры `FInGameTime::Now().ToString()` и чтения координат игрока — кандидаты первой операции, не выполненная проба.

Прямой сетевой API AngelScript не найден в ограниченной сверке официальных индексов; отсутствие имени не доказывает невозможность. Широкие строки текущего EXE `HttpServer` и `RemoteControl` оказались в контексте `EAlkimiaLaunchEmbargo_FileSource::HttpServer` и `UMvnRemoteControlManager`. Они не подтверждают наличие сетевого сервера Unreal Remote Control. Строки `FHttpServerModule`, `RCWebControlEnable` и другие проверенные привязки не найдены ограниченным поиском.

### FConsoleCommand

Статически найден тип и binding конструктора `void f(const FString& Name, const FName& FunctionName)`. В текущем EXE фактический callable **VA `0x14419b7e0`**, file offset **`0x419ade0`**, заканчивается `ret` на `0x14419b817`.

Ограниченная дизассемблировка показывает преобразование `FunctionName` во временную строку, обнуление 24 байтов объекта и освобождение строки. В полном проверенном теле нет использования аргумента `Name`, поиска функции/модуля или регистрации callback. Общий thunk `0x1420a7530` не является самим конструктором.

**Вывод:** этот binding не предоставляет подтверждённую регистрацию команды в текущей сборке. Консольный канал нельзя строить только на наличии типа в справочнике. Поведение конкретного binding не доказывает компиляционное исключение всей системы debugger.

REA `6.7.0` использован для диагностики доступных возможностей и чтения PE-ресурсов. Управляемый native-provider оказался недоступен; указанный вывод дополнен ограниченной статической дизассемблировкой Capstone из файла. Runtime-память, инъекция и изменение EXE не использовались.

## Дескриптор и версии

Официальное поле — `modVersion`; совместимость игры задаётся `dependencies` с `name: "G1R"` и `requiredVersion`. Поле `GameVersion` в официальном формате не описано. API хранит значения как `FString`, но это не доказывает принятие `1.0.0-dev.N` сравнением версий. Проверка загрузчика технической версии остаётся открытой до создания рабочего пакета.

## Unreal MCP и отдельный редактор

[Официальный Unreal MCP Epic](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-mcp-in-unreal-editor) описан как экспериментальный `ModelContextProtocol` в UE 5.8. Полезные архитектурные решения: сервер отдельно от toolsets, запрос каталога по требованию, структурированные схемы, последовательное выполнение на игровом потоке. Runtime-модули можно включать в специально собираемые cooked/shipping приложения, но их присутствие в выпущенной G1R на модифицированном UE 5.4.3 не следует из этих материалов.

Для AngelScript-кода отдельный Unreal Editor не нужен: по [официальному Setup](https://alkimiainteractive.github.io/G1R-Modkit/getting-started/angelscript-setup/) его возможности предоставляет игра. Для создания/cooking нового контента [руководство Alkimia](https://alkimiainteractive.github.io/G1R-Modkit/unreal-project/content-cooking/) допускает обычный UE **5.4** от Epic. Установка UE 5.8 не добавит его MCP в установленную игру. Редактор не установлен этой задачей и не является обязательной зависимостью текущей проверки канала.

## Состояние контрольной точки

Версия и полный объём согласованы, среда источников подтверждена, диагностика воспроизводима. Э1 не пройден: пригодный двусторонний канал не доказан, отсутствующий LSP текущего выпуска подтверждён Alkimia. Можно продолжать независимые локальные инструменты и контрактные исследования; проверка официального сетевого канала зависит от следующего обновления. Альтернативный UE4SS/native backend или возврат файлового mailbox требуют отдельного архитектурного решения. PLAN-001 остаётся активным; полный инструмент ещё не реализован.
