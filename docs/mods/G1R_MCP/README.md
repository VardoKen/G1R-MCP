# G1R MCP: назначение и архитектура

## Назначение и текущее состояние

Состояние на **05.11.2026**: версия исходников **1.0.0-dev.107**, согласованная целевая публичная версия — **1.0.0**. Назначение G1R MCP — полноценный инструмент исследования, разработки и отладки официальных модов Gothic 1 Remake через Modkit / AngelScript с помощью ИИ-агентов. Перенос пользовательских модов с UE4SS — промежуточный практический рубеж, а не полная цель моста. Рабочие пакеты используют `GothicMod.json`; исходники и инструменты UE4SS остаются отдельным контуром.

Dev.107: input-массивы собственных scalar DTO приняты: пустой массив → 0, смешанные элементы → 1000, дубликаты → −18. Reflection fixture — stride 24, alignment 8; проверка адреса использует alignment, размер копии — stride. Значения кодируются с нулевым padding, cleanup подтверждён. Общий цикл — 21/21 typed-вызовов и 9/9 проверок. [Подтверждения](../../../artifacts/dev107-typed-input-live-complete.json).


Рабочий runtime — **1.0.0-dev.107**, 51 инструмент. Scalar DTO array input/return и прежние int32/FName/enum-сценарии приняты в одном live-цикле: 21/21 typed-вызовов, 9/9 итоговых проверок. [Результат dev.107](../../../artifacts/dev107-typed-input-live-complete.json).

Сервер регистрирует **51 MCP-инструмент**, но это число не означает завершения всей цели [PLAN-001](plans/PLAN-001-active-implementation.md). Реализованы конкретные контракты исследования, работы с пакетами, состояния и вызовов. Доступность игровой операции определяется состоянием native-моста, фактической отражённой сигнатурой и результатом вызова; оставшиеся пробелы разработки и отладки перечислены ниже.

| Область | Реализованный результат |
| --- | --- |
| Исходники и API | Идентификация источников, сверка с игрой, поиск файлов, текста, типов и функций, точное чтение с SHA-256. Статический каталог не заменяет reflection или compiler AST. |
| Пакеты и development-сеанс | Создание, чтение и изменение рабочих пакетов, структурная проверка, ScriptPatches, экспорт и проверка ZIP; рецепт запуска, companion-пакеты, наблюдение процесса, staging и применение выбранного файла, загрузка DLL, остановка своей сессии и адресный ввод клавиши. |
| Состояние и наблюдения | Поиск объектов, выборка свойств и функций, чтение массивов, структур, поддержанных set/map, вложенных собственных Struct/Array DTO, snapshots и их сравнение, управляемые watches с владением, последовательностями событий и сведениями о потерях. |
| Вызовы и диагностика | Типизированный `ProcessEvent` по проверенной сигнатуре, входы и результаты поддержанных типов, чистые output-параметры и UObject-массивы, наблюдаемая диагностика компилятора и ошибок AngelScript, состояние и адресное завершение MoviePlayer wait. |

Точные типы, поля ответа, требования к среде и границы операций описаны в [локальных инструментах](local-tools.md) и [нативном маршруте](native-route.md). Актуальный каталог возвращает `g1r_capabilities`; его контракты формируются из регистрации инструментов и `src/g1r_mcp/tool_catalog.py`.

## Архитектура подключения и выполнения

```text
Чаты Codex / MCP-клиенты
    ↕ Streamable HTTP 127.0.0.1:27124/mcp
Один общий G1R MCP Server
    ↕ loopback TCP 127.0.0.1:27123
Автономная G1R_MCP.dll
    ↕ очередь игрового Tick / UObject / UFunction / ProcessEvent
Gothic 1 Remake
```

Все чаты текущей установки Codex используют один HTTP-сервер. Новый чат не запускает отдельную копию сервера. В Windows загрузчик виртуального окружения и рабочий Python-процесс могут составлять одну постоянную пару. Отдельный stdio-режим сохранён для клиентов, которые явно запускают собственный дочерний сервер.

Сервер разделяет чтение источников, работу с workspace, управление development-процессом и native-вызовы. Для совместной работы используются HTTP-владение игровой сессией и владельцы watches. Ссылки на объекты и токены сигнатур относятся к общей native TCP-сессии; они не являются отдельными правами HTTP-чата. При reconnect требуются новые ссылки. Проверки identity/serial и поколений мира и скриптов защищают действительность отражённых контрактов; их точная область действия указана в [нативном маршруте](native-route.md).

DLL выполняет игровые обращения через подтверждённый Tick. Чтение контейнеров и вложенных DTO использует копии данных и повторную проверку metadata и headers; неподдержанные компоненты сохраняют ошибки и признак `partial`. Перед типизированным вызовом повторно проверяется отражённый контракт. После неопределённого результата доставки игровая команда автоматически не повторяется.

Native DLL загружается внешним загрузчиком из runtime-комплекта и остаётся в процессе до закрытия игры; UE4SS для этого маршрута не используется. Официальный development-helper — отдельный AngelScript-пакет, подключаемый к выбранному сеансу. Он не превращает DLL в официальный runtime-пакет для установки из Steam.

## Рабочий и переносимый контуры

`g1r_status` и `g1r_capabilities` показывают сервер и каталог, но не проверяют живую игру. Для игрового состояния используется `g1r_native_status`. Рецепт development-сеанса фиксирует выбранные пакеты и артефакт; ответ `launch_requested` требует последующего подтверждения точного процесса и native-готовности.

Корни Modkit, workspace, игры и server runtime задаются раздельно. Параметр `--runtime-root` выбирает комплект PowerShell-инструментов, DLL и loader; он используется и shared-запуском. Python wheel устанавливает сервер, а native-ресурсы и официальный helper предоставляются переносимым комплектом. Один wheel без этих ресурсов не обеспечивает полный игровой development-сеанс. [Команды и состав подключения](native-route.md).

Работа с пакетом, экспорт ZIP или успешная запись staged-файла не доказывают компиляцию, применение ScriptPatches или исполнение нового тела. Перезагрузка тел функций подтверждена; изменения классов, свойств и defaults требуют перезапуска. Создание и cooking ресурсов остаются отдельным контуром Unreal Editor.

## Подтверждение и границы готовности

| Статус на dev.107 | Что готово или остаётся неполным |
| --- | --- |
| Реализовано и проверено в игре | Native TCP/Tick, выбранные типизированные вызовы и lifecycle, чтение объектов и поддержанных значений, вложенный `FExpApiResult`, UObject output-массивы, int32/FName/enum input/return-массивы, scalar DTO array input/return и собственные scalar-структуры, snapshots/watches. Перезагрузка тел функций и применение двух конкретных ScriptPatches подтверждены прежними игровыми сериями; это не подтверждение любого нового пакета. |
| Реализовано и проверено локально | Поиск и точное чтение исходников, редактура и структурная проверка пакетов, построение diff, экспорт ZIP/manifest, установленный wheel с runtime-root. Эти операции не компилируют и не исполняют пакет. |
| Диагностика подтверждена; результат компиляции не удостоверяется | Native compiler formatter: ошибка компиляции подтверждена в [dev.27](../../../artifacts/dev27-hot-errors-result.json). Чтение предоставленного отчёта, staged-file hot reload и наблюдение scripts-generation реализованы. Отчёт и текущий SHA-256 не связаны доказанно с конкретной успешной компиляцией; `compiled=true` для выбранных байтов не подтверждается. |
| Частичная runtime-диагностика | Наблюдаемые ошибки текущего AngelScript `ProcessEvent` со сведениями о стеке. Это не debugger и не полная история ошибок или доказательство завершения скрипта. |
| Не реализовано или не подтверждено | Произвольная VM-компиляция/eval, debugger с breakpoint/step/locals, универсальный invoke вложенных DTO и контейнеров, общая delegate-подписка. Их нет среди готовых контрактов. |
| Итоговая приёмка не закрыта | Локальные тесты пройдены; есть выбранные игровые и последовательные объёмные сценарии. Но итоговые численные критерии производительности/стоимости и стабильности Э8 ещё не зафиксированы. Это остаток исходного плана, а не требование написать новый тест под каждую операцию. |
| Отдельный контур, не функция моста | Создание и cooking игровых assets в Unreal Editor; мост умеет хранить и экспортировать уже подготовленные файлы компонентов. Публичный выпуск и установка native DLL из Steam не выполнены. |

Shared-приёмка dev.99 подтвердила версию сервера и runtime-root, общий HTTP-адрес, **51 инструмент**, отсутствие игровой заявки и закрытую игру. Каноническая DLL dev.99 доступна как артефакт; эта приёмка не загружала её в игру. Базовый Python-набор dev.99 — **736/736 PASS**, без failures, errors и skips, 484,948 с; один из 737 обнаруженных тестов исключён до запуска из-за dirty-редакции helper-дескриптора с `loadOrder: "Normal"`, его результат не входит в PASS. Полный CTest — **39/39 PASS**, 7,99 с. [Подробности проверок и исключённого случая](../../tests/G1R_MCP/README.md).

Игровые проверки dev.96 подтвердили чистые UObject output-массивы, полный вложенный `FExpApiResult` с собственными структурами и массивами, стабильные snapshots/watches и объёмную серию чтения состояния. Сохранённый nested-ответ проверен по каноническим reflected-именам без дополнительного игрового вызова; исходная ошибка клиентской проверки сохранена в receipt. Свои игровые процессы завершены, заявки освобождены. Отдельная приёмка установленного wheel dev.98 подтвердила доступ к ресурсам через runtime-root и локальные process/recipe операции; она не запускала игру.

Источники актуального состояния — текущий код, `dev99-shared-acceptance.json`, `dev96-live-acceptance.json`, `dev96-volume-acceptance.json`, `dev98-wheel-installed-acceptance.json`, `python-full-dev99-current.txt` и `native-ctest-dev99-current.txt`. Полные результаты и точные границы подтверждения ведутся у владельца [набора проверок](../../tests/G1R_MCP/README.md).

Чтение native compiler diagnostics и предоставленного отчёта реализовано; `compiler_api_available=true` означает доступ к formatter, а не универсальному компилятору. Пустой отчёт не доказывает успешную компиляцию. Наблюдаемая ошибка текущего `ProcessEvent` и захваченный стек не являются историей всех ошибок runtime; отсутствие записи не доказывает завершение скрипта. Полноценная разработка и отладка остаются целью моста с указанными пробелами, а не результатом одного факта регистрации 51 инструмента.

**Публичный выпуск 1.0.0 не выполнен.** Техническая версия dev.107 и предыдущие проверенные wheel/runtime-комплекты не являются публикацией в PyPI, Steam Workshop или Nexus Mods. Поддержка разработки официальных пакетов не означает готового распространения native DLL через Steam.

## Накопленный результат для 1.0.0

Это заметки для будущего публичного выпуска по совокупности dev.1–dev.107, а не changelog опубликованной версии **1.0.0**. Текущая рабочая версия — **1.0.0-dev.107**.

- **Подключение:** 51 MCP-инструмент, один общий Streamable HTTP-сервер для чатов Codex, отдельный stdio-режим, внешний native TCP-мост и выполнение через игровой Tick без UE4SS.
- **Изучение API:** идентификация Modkit и сверка с игрой, поиск исходников, типов и функций, точное чтение с хешами и продолжение страниц; статический поиск не заменяет отражённый игровой контракт.
- **Разработка пакетов:** создание и защищённая редактура официальных пакетов, структурная проверка, построение ScriptPatches, экспорт и проверка ZIP, companion-пакеты, staging и применение выбранных файлов; успешная запись не подтверждает компиляцию или применение патча.
- **Development-сеанс:** воспроизводимый рецепт, подтверждение точного процесса, адресная загрузка DLL и ввод клавиши, владение общей игрой и остановка своей сессии; перезагрузка тел функций подтверждена, изменения классов, свойств и defaults требуют перезапуска.
- **Чтение состояния:** ссылки на объекты, выборка свойств и сигнатур, поддержанные Array/Set/Map, math DTO, вложенные собственные структуры и массивы, object/class/weak descriptors; копии данных и повторная проверка metadata сохраняют явный `partial` для неподдержанных полей.
- **Наблюдения:** snapshots и сравнение, управляемые watches, владелец и последовательности событий, сведения о потерях, очистка и отзыв контекста при смене native-сессии, выбранного мира или скриптового поколения.
- **Типизированные действия и диагностика:** проверка сигнатуры перед `ProcessEvent`, поддержанные входы, возвраты и output-параметры, UObject-массивы, compiler diagnostics и наблюдаемые ошибки AngelScript со стеком; неопределённый результат не запускает автоматический повтор, произвольная VM-компиляция и debugger не объявлены готовыми.
- **Поставка и проверка:** установленный Python wheel с явным `--runtime-root`, переносимый комплект native-ресурсов и отдельный официальный helper, локальные тесты и сохранённые игровые приёмки; публичный выпуск и распространение native DLL через Steam этим не выполнены.

## История и владельцы сведений

Результаты dev.1–dev.14 относятся к историческим версиям. В частности, dev.14 с 38 инструментами, ранние ограничения структур, компилятора и поколений среды не описывают текущую базу. Подробные записи сохранены в [истории завершённых задач](task-history/README.md); этот README не дублирует журналы отдельных проб.

Собственный loopback TCP и игровая очередь составляют действующий канал. UE4SS-мосты использовались как исторические источники решений; их Lua-механизмы не доказывают доступность официального AngelScript API. Файловый mailbox и fallback не входят в архитектуру G1R MCP.
