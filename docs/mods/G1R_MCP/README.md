# G1R MCP: назначение и архитектура

## Назначение и согласованная основа

Мост предназначен для разработки модов Gothic 1 Remake с помощью ИИ-агентов через MCP. Пользователь выбрал официальный Modkit / AngelScript и согласовал целевую публичную версию **1.0.0** с полным объёмом инструмента 30.10.2026. Это включает справочник API, чтение состояния, наблюдения, типизированные действия и инструменты создания/проверки модов через подтверждённые возможности. Название `G1R MCP` относится к подпроекту; идентификатор и структура будущего игрового пакета пока не определены.

Текущее состояние подпроекта описано в [корневом README](../../../README.md). Подтверждения и точные версии изученных источников находятся в [реестре источников](references/README.md).

Выполняется [PLAN-001](plans/PLAN-001-active-implementation.md), 30.10.2026. Техническая версия **1.0.0-dev.7**: внешний MCP-сервер с [локальными инструментами](local-tools.md) и [нативным маршрутом](native-route.md). Приоритет — пригодность для начала переноса модов 31.10.2026. Пользователь поручил продолжать разработку до его команды остановиться и разрешил необходимые проверки. План зарегистрирован в [едином реестре](deferred-changes.md).

## Архитектура и текущее состояние

```text
MCP-клиент
    ↕
Внешний G1R MCP Server
    ↕ localhost TCP
Автономная DLL G1R_MCP: очередь игрового Tick
    ↕ UObject / UFunction / ProcessEvent
Игра
```

Внешний сервер предоставляет 32 инструмента справочника, рабочих пакетов и нативных операций. DLL загружается из подпроекта в процесс без UE4SS; выполняет очередь и наблюдения в подтверждённом игровом потоке. Через MCP проверены снимки/наблюдения, ObjectProperty/ClassProperty-аргументы и результаты, UClass/TSubclassOf и ограничения наследования. FName/enum читаются как текст/число с отдельными метаданными; нулевые входы с FName/FString-возвратами подтверждены в dev.7. Собственный официальный пакет вернул `1`, затем `2` после изменения тела без перезапуска. Универсальная VM-компиляция, диагностика компилятора и остальные сложные аргументы не реализованы.

В dev.7 реальный MCP-сеанс подтвердил маркер `71`, повторные FName-entry/`None` и строку/пустую строку, стабильное наблюдение и освобождение выделенного строкового результата. Ограниченный cleanup завершил свою игровую сессию; список процессов пуст. Локальная сборка переносимого комплекта содержит 47 файлов с проверенным manifest, без копии игры/Modkit и без включённых виртуальных сред или пользовательских данных.

При первом подключении initialize-инструкция и `g1r_capabilities` описывают порядок: рецепт/процессы → явный development-запуск → точный процесс/хеш DLL → загрузка → native-status → явное включение Tick при необходимости → ready → поиск объекта/сигнатура → выбранный вызов → явная остановка своей сессии. Для уже работающего моста достаточно native-status и новых сессионных ссылок. TCP-клиент один; reconnect отменяет владение прежними handles/наблюдениями. Полные исходники читаются exact-инструментами с SHA-256, список рабочих файлов продолжается через `next_offset`; поиск и структурная проверка не доказывают компиляцию или применение ScriptPatches.

Группы полного объёма, конкретные API ещё уточняются:

- **Изучение API:** поиск типов, функций, параметров и связанных игровых исходников с указанием источника сведений.
- **Изучение состояния:** поиск доступных объектов, снимки состояния и наблюдения за изменениями через подтверждённые API.
- **Действия:** типизированные игровые команды с определёнными параметрами, результатом и ошибками.
- **Разработка модов:** работа с источниками и пакетами в рабочем каталоге, диагностикой, компиляцией и перезагрузкой в границах реально подтверждённого API игры. Создание и cooking ресурсов рассматриваются как отдельный контур Unreal Editor.

Произвольная компиляция и исполнение внешнего AngelScript-кода не подтверждены и не считаются готовой возможностью моста.

## Опыт существующих мостов

Разработка `MCP to UE4SS`, указанная пользователем, служит источником архитектурных решений. В ней изучены протокол, сервер, управление выполнениями и связанные тесты. Для новой реализации полезны:

- каталог реальных возможностей с причинами недоступности и требованиями к состоянию среды;
- идентификаторы клиентов и владение заданиями, результатами и подписками;
- поколения среды и проверка действительности ссылок на объекты после смены мира или перезагрузки;
- отдельные состояния принятия, выполнения, завершения и очистки задания;
- отсутствие автоматического повтора игровой команды после неопределённого результата доставки;
- ограниченные очереди событий, последовательность сообщений и явные сведения о потерях и усечении.

Это кандидаты для самостоятельной адаптации. Их конкретная реализация в G1R MCP не выбрана. Lua-исполнители, совместимость DLL с UE4SS, поиск чужих Lua-контекстов и механизмы UE4SS-рефлексии не подтверждают аналогичные возможности AngelScript.

В прежнем `G1R-UE4SS-LUA-Bridge to MCP` файловый mailbox был признан неудачным решением, а файловый fallback исключён из целевой архитектуры. Это подтверждённая история прежнего моста, которую необходимо учитывать; наличие файлового API в Modkit само по себе не означает выбор файлового обмена для G1R MCP.

## Что ещё требует исследования

| Вопрос | Подтверждённое состояние на 31.10.2026 |
| --- | --- |
| Двусторонний канал сервер ↔ игра | Нативный loopback TCP, DLL и Tick подтверждены; полный development-цикл проходит через MCP. [Текущий контракт](native-route.md). |
| JSON и файловые функции | Присутствуют в официальном справочнике. Работоспособность в установленной сборке игры не проверена. |
| Режим разработки AngelScript | Development-запуск, загрузка пакета и reload тела проверочного метода подтверждены. Отдельный debugger/compiler API недоступен; применение ScriptPatches в проверенных конфигурациях не подтверждено. |
| Жизненный цикл и поток исполнения | Нативная очередь из FEngineLoop::Tick подтверждена; DLL до закрытия игры, без выгрузки. Смена мира пока не проверена. |
| Объекты и наблюдения | Сессионные ссылки, свойства FName/enum/Object/Class, отражённые UFunction, ограниченные snapshots/watches и их очистка реализованы. Serial, смена мира и полноценные подписки ещё не подтверждены. |
| Совместимость с обновлением | Steam public build `26295476`; все 7 280 файлов Script Modkit совпали с установленными. Работоспособность конкретных вызовов ещё требует проб. |

Первая сквозная проверка выполнена через собственный нативный канал: MCP-запрос, объект текущей игры, свойства, отражённая AngelScript-функция и структурированный ответ. В dev.3 собственный проверочный пакет скомпилирован и загружен; изменение тела метода подхвачено без restart.
