# Проверки G1R MCP: локальные инструменты и нативный маршрут

Дата: **30.10.2026**. Версия **1.0.0-dev.3**, официальный SDK **mcp 2.3.0**, Python **3.14.6**, MSVC C++20 x64. Проверены автономные сценарии и текущая игровая вертикаль; набор не является приёмкой полного выпуска 1.0.0.

## Автономный набор

Из корня подпроекта:

```powershell
uv sync --locked
.venv\Scripts\python.exe -B -m unittest discover -s tests -q
```

**114 Python-тестов прошли**. Набор включает среду, диагностический debugger-протокол, источники, дескрипторы, нативный клиент, рабочие файлы, сравнение снимков и сквозные MCP stdio-сессии.

- [Среда](../../../tests/test_game_environment.py): allowlist Steam-метаданных, повреждённый ACF, несовпадающий каталог, отсутствующие/различающиеся скрипты, предел списков, symlink и отсутствие изменений файлов.
- [Протокол](../../../tests/test_angelscript_debug_protocol.py): асимметрия направлений, фрагментация и несколько кадров, ограничение/усечение, UTF-8/UTF-16, однократные запросы и отсутствие повтора после timeout. Socketpair заменяет игру.
- [Источники](../../../tests/test_sources.py): разрешённые корни, реальные строки, лексические типы, partial scan, ограничения Unicode-ответа, повреждённый/изменённый файл и выход за корни.
- [Пакеты](../../../tests/test_packages.py): официальный дескриптор, зависимости, content-only пакет, duplicate/NaN/Infinity, неизвестные поля и отсутствие записи.
- [MCP-сессия](../../../tests/test_mcp_server.py): дочерний stdio-сервер, initialize/list 23 инструментов, исходные локальные вызовы, structured content, ошибки пути/лимита и сохранение входных файлов.
- [Native-клиент](../../../tests/test_native_client.py): framing/Unicode/ID, deadline, обрыв, конкурентные вызовы и отсутствие повтора.
- [MCP ↔ native](../../../tests/test_mcp_native.py): исходные нативные функции, каталог 23 инструментов, параметры и неопределённость эффекта после ошибки без повторного invoke.
- [Рабочая база](../../../tests/test_workspace.py) и [MCP-редактирование](../../../tests/test_mcp_workspace.py): создание/чтение/замена файлов, SHA-256-конфликты, запрет записи в Modkit, Windows devices/streams/reparse/junction, UTF-8, пределы и отсутствие промежуточных файлов после отказов.
- [Сравнение снимков](../../../tests/test_snapshots.py): типы/значения, неполный охват, чужая сессия/процесс, фактическая нативная схема, неподдержанные поля, размеры и отсутствие изменения входных копий.
- [MCP-наблюдения](../../../tests/test_mcp_observations.py): snapshot/watch/read/stop/forget, аннотации, потери событий, терминальный результат и обрыв старта без повтора с новым владельцем после reconnect.
- [Компиляционная проба](../../../tests/test_compile_probe.py): изолированный пакет, ровно одна замена константы с ожидаемым хешем, сохранение дескриптора и пользовательских изменений, проверка сигнатуры и параметров диагностического инструмента.

## Нативная сборка и автономная проверка

```powershell
.\tools\build_native.ps1
```

CMake собирает DLL, загрузчик и два test executable. **CTest: 2/2 прошли**. `native_transport` проверяет кадры/Unicode, неправильный JSON/версию/размер/ID, timeout, повторные start/stop, лимит запросов, занятый порт и уведомление о закрытии сессии. `native_observations` проверяет baseline/changes, интервалы, ёмкость и байтовые потери, срок/остановку/очистку, владельца, прекращение чтений и границы скалярных аргументов. Зависимости закреплены в `native/CMakeLists.txt`: JSON 3.12.0 и конкретный commit MinHook.

Загруженную DLL перед пересборкой освобождает только закрытие игры. Сборка не запускает игру или загрузчик.

## Проверенная игровая вертикаль

После запуска через Steam и появления главного меню:

```powershell
.\tools\load_native.ps1
.venv\Scripts\python.exe -B tools\probe_native_route.py --enable --call-verified-as
```

В dev.2 подтверждены status/ready и `CM_Attack.ShouldInvalidateAttack()` → `false` через реальную MCP-сессию. В dev.3 отдельная stdio-сессия получила **23 инструмента** и готовность DLL; выбранные логические свойства прочитаны в снимках, сравнены копии, получены baseline и terminal наблюдения, подтверждены остановка/очистка и forget. Закрытие сессии с активным наблюдением проверено отдельно: новый клиент получил `unknown_watch` для прежнего наблюдения и `stale_handle` для старой ссылки. Поток результатов совпал с игровым Tick (**38908** в проверенной сессии). Никакие сохранения не загружались. [Источники, контракты и границы](../../mods/G1R_MCP/native-route.md).

## Компиляция и hot reload изолированного пакета

[prepare_compile_probe.py](../../../tools/prepare_compile_probe.py) создаёт только `GothicMod.json` и один `.as` из [fixture](../../../tests/fixtures/angelscript_probe/GothicMod.json) в отдельном `artifacts/` каталоге. Подготовка не запускает игру и не доказывает компиляцию. Development-запуск с `-ModsDirectory` и `-Mods` выбирает этот пакет; параметры не записываются в постоянную игровую конфигурацию.

В текущей игре CDO `Default__G1RMCPCompileProbe` и прочитанная сигнатура `ReadProbeValue()` подтвердили загрузку класса. Через MCP метод вернул **1**. Замена единственной константы на **2** с проверкой SHA-256 привела к результату **2** после hot reload без перезапуска процесса. Проверялся только этот метод и изменение тела функции; новые классы, поля/defaults, произвольная VM-компиляция и полный поток диагностик этим не подтверждены.

[probe_live_mcp.py](../../../tools/probe_live_mcp.py) воспроизводит проверку уже запущенной игры и загруженной DLL:

```powershell
.venv\Scripts\python.exe -B tools\prepare_compile_probe.py --workspace-root '.\artifacts\compile-probe'
.venv\Scripts\python.exe -B tools\probe_live_mcp.py --expected-value 1
```

Подготовленный пакет нужно отдельно включить при development-запуске. После проверки baseline явный `--reload --probe-workspace <каталог> --expected-sha256 <хеш исходника>` меняет только проверочную константу. `--observations` требует явно заданных `--observe-query`, `--observe-class` и одного или нескольких `--property`; игра и DLL этим инструментом не запускаются.

## Read-only сверка установленной среды

```powershell
python -B tools/inspect_game_environment.py `
  --game-root 'E:\SteamLibrary\steamapps\common\Gothic 1 Remake' `
  --modkit-root 'C:\Users\Vardo\Documents\G1R Mods\G1R-Modkit' `
  --steam-manifest 'E:\SteamLibrary\steamapps\appmanifest_1297900.acf' `
  --hash-executable
```

Инструмент читает только явно заданные источники и выдаёт JSON. Он не запускает игру, не читает сохранения и не изменяет файлы. Совпадение скриптов не подтверждает работоспособность конкретного API.

## Запуск development mode через Steam

[start_g1r_development.ps1](../../../tools/start_g1r_development.ps1) сохраняет наблюдавшийся `-FromModManagementUI`, добавляет разовые согласованные параметры и использует Steam AppID `1297900`. Проверен синтаксис и `-WhatIf` в PowerShell 7 / Windows PowerShell 5.1; файл UTF-8 с BOM для совместимости PS5.1.

```powershell
.\tools\start_g1r_development.ps1 -Restart -WhatIf
```

Без `-WhatIf` скрипт запускает игру; `-Restart` штатно закрывает проверенный текущий процесс. Команда используется только в рамках существующего прямого разрешения запуска. Список модов, Steam LaunchOptions, cache и конфигурация не изменяются; фактическая активация модов по одной командной строке не доказывается.

## Разовая проба debugger

```powershell
python -B tools/probe_angelscript_debugger.py --timeout 3
```

По умолчанию одно подключение, только получение handshake и `Disconnect` при установленном соединении. `--request-database` однократно запрашивает базу, сохраняя лишь метаданные размера/количества. `--start-debugging` и `--evaluate` включаются явно; Evaluate допускает только ASCII-литерал и явный `frame-id`. Они не выполнялись в игре: подключение не установлено.

Формат закреплён по открытому клиенту Hazelight ревизии `ffc7ab2948589abb04200b7dcedd326eaeaf7a4d`. Диагностические лимиты настраиваются; они не являются требованиями будущего продукта. Нет Pause/Continue/StopDebugging или скрытого повтора запросов.

## Граница подтверждения

Проверены игровой поток, ограниченные снимки/наблюдение свойств, существующий AngelScript-вызов и компиляция/hot reload изолированного маркера через самостоятельную DLL. Длительная работа, смена мира, serial объектов, загрузка сохранения, сложные сигнатуры и широкие действия не проверены. История исходной debugger-диагностики хранится в [результатах среды](../../mods/G1R_MCP/references/2026-10-30-environment-and-transport.md); рабочий маршрут описан в [нативном контракте](../../mods/G1R_MCP/native-route.md).
