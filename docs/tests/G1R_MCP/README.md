## Нативная сборка и автономная проверка

```powershell
.\tools\build_native.ps1
```

CMake собирает DLL, загрузчик и автономные test executable. `native_transport` проверяет кадры/Unicode, неправильный JSON/версию/размер/ID, timeout, повторные start/stop, лимит запросов, занятый порт и уведомление о закрытии сессии. `native_observations` проверяет baseline/changes, интервалы, ёмкость и байтовые потери, срок/остановку/очистку, владельца, прекращение чтений, границы скалярных/объектных аргументов и объектные значения снимков. `native_object_query` проверяет поиск по имени/пути, `exact_path`, Unicode, NUL и предел пути. Зависимости закреплены в `native/CMakeLists.txt`: JSON 3.12.0 и конкретный commit MinHook.

Для набора dev.10 **CTest: 13/13 прошли**. Новые `native_array_page` проверяют заголовок, границы страницы и адресное переполнение; `native_struct_values` — отражённые размеры/смещения XYZ/Pitch/Yaw/Roll и конечные числовые значения. Сохранён `native_object_serial` для строгого равенства наблюдаемого serial объекта/класса, zero и отзыва ссылки после изменения serial. Проверка не выделяет serial и не доказывает защиту от ABA при нулевых serial. Сохранены `native_enum_arguments` для строгого целочисленного JSON, диапазонов и объявленных значений UEnum, `native_name_return` для копируемого FName, `native_string_return` для FString/освобождения результата, `native_class_arguments` для UClass/PropertyClass/MetaClass, `native_function_query` для фильтра до ограничения выдачи, `native_loader_identity` для исходного PID/FILETIME/EXE и `native_enum_values` для числовых типов, layout, aliases и пределов имён; загрузчик и DLL собраны в Release.

Ошибка после выполненного `ProcessEvent` сохраняет `executed: true`, `may_have_executed: true`, `do_not_retry: true`, даже если декодирование результата не удалось. Fault самого вызова помечает эффект неизвестным; совместимость ссылочного аргумента проверяется до вызова и непосредственно перед ним. TCP-обрыв не вызывает автоматического повторения.

Загруженную DLL перед пересборкой освобождает только закрытие игры. Сборка не запускает игру или загрузчик.

## Компиляция и hot reload изолированного пакета

[prepare_compile_probe.py](../../../tools/prepare_compile_probe.py) создаёт только `GothicMod.json` и один `.as` из [fixture](../../../tests/fixtures/angelscript_probe/GothicMod.json) в отдельном `artifacts/` каталоге. В текущей игре CDO `Default__G1RMCPCompileProbe` и прочитанная сигнатура `ReadProbeValue()` подтвердили загрузку класса. Через MCP метод вернул **1**. Замена единственной константы на **2** с проверкой SHA-256 привела к результату **2** после hot reload без перезапуска процесса. Проверялся только этот метод и изменение тела функции; новые классы, поля/defaults, произвольная VM-компиляция и полный поток диагностик этим не подтверждены.

[probe_live_mcp.py](../../../tools/probe_live_mcp.py) воспроизводит проверку уже запущенной игры и загруженной DLL:

```powershell
.venv\Scripts\python.exe -B tools\prepare_compile_probe.py --workspace-root '.\artifacts\compile-probe'
.venv\Scripts\python.exe -B tools\probe_live_mcp.py --expected-value 1
```

Подготовленный пакет нужно отдельно включить при development-запуске. После проверки baseline явный `--reload --probe-workspace <каталог> --expected-sha256 <хеш исходника>` меняет только проверочную константу. `--observations` требует явно заданных `--observe-query`, `--observe-class` и одного или нескольких `--property`; игра и DLL этим инструментом не запускаются.
